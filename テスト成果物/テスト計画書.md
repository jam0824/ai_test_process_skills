# テスト計画書

## 1. テスト目的

老後資金シミュレーターが、`spec/仕様書.md` v1.3 に定義された簡易計算モデル、画面操作、オフライン動作、注意表示、証跡方針に一致していることを確認する。特に、利用者が老後資金の目安として参照する計算結果を過信しないよう、計算正確性、入力異常時の安全性、プライバシー説明、シミュレーション限界の表示を重点的に検証する。

本フェーズではテスト戦略を定義し、後続のテスト分析・設計・ケース作成・自動化・実行で必要な深さを明確にする。詳細なテストケース、実装、実行は後続フェーズで扱う。

## 2. ドキュメント

| `sample_app/README.md` | 利用者向け説明、起動方法、機能概要、テストファイルの説明を確認する。仕様と矛盾する場合は仕様書を正とする。 |

## 4. テストスコープ

### 4.1 対象範囲

| 区分 | スコープ |
|---|---|
| 仕様準拠 | `spec/仕様書.md` v1.3 を正として、READMEと実装が一致していることを確認する。 |
| 計算ロジック | 手取り、所得税ブラケット境界、ライフサイクル収入判定、投資利回り、投資補填、ランダムイベント、給与変更を対象にする。 |
| UI操作 | すべての入力欄、開始ボタン、給与変更トグル、給与変更追加・削除、結果表示を対象にする。 |
| 入力異常 | 空欄、0、負値、範囲外、有限数でない値、ブラウザが許容する指数表記、給与変更の無効設定を対象にする。 |
| セキュリティ/プライバシー | 外部通信なし、外部依存なし、永続化なし、`textContent` による結果表示、ユーザー入力を埋め込まない静的 `innerHTML` を対象にする。 |
| 性能 | 仕様の標準測定条件での計算処理・画面描画・10回連続実行を対象にする。 |
| 互換性 | Playwrightの `chromium`、`firefox`、`webkit` を代表環境とし、Safari実機固有差異はWebKitで再現できない場合のみ手動確認対象とする。 |
| アクセシビリティ | WCAG正式適合ではなく、キーボード操作、ラベルの分かりやすさ、結果表示の読み取りやすさを対象にする。 |
| 証跡 | Markdown/CSVサマリ、実行ログ、Playwright JSON、失敗時スクリーンショット/trace/video、手動確認記録の保存方針を対象にする。 |

### 4.2 対象外・制約

| 区分 | 内容 | 残存リスク/代替確認 |
|---|---|---|
| 実税制・実年金制度 | 給与所得控除、復興特別所得税、各種控除、NISA、繰上げ・繰下げ年金などは対象外。 | 仕様上の制約事項として、注意表示とREADME説明が過信を抑止していることを確認する。 |
| インフレ/デフレ | 将来の物価変動は対象外。 | 注意表示と制約事項の明示を確認する。 |
| JavaScript無効環境 | 動作対象外。 | 前提条件として記録する。 |
| 800x600未満 | スマートフォン幅はベストエフォート。 | 正式な合否対象にしないが、重大な表示崩れがあれば残リスクとして記録する。 |
| Safari実機固有差異 | WebKitで再現できない差異のみ手動確認。 | 実機確認要否は後続フェーズで `要確認` として扱う。 |
| 開発者ツール等で任意スクリプト実行済み環境 | 完全防御は対象外。 | 通常入力、貼り付け、DOM値として取得される入力差異を対象にする。 |
| 正式回帰HTMLの実行 | Phase 1では実行しない。 | 後続フェーズで存在確認し、存在しない場合は未実装/未実行/N/Aとして可視化する。 |

| 証跡 | Markdown/CSVサマリ、実行ログ、必要なスクリーンショット/trace/video、手動確認記録が `テスト成果物/` 配下に保存される。 |
