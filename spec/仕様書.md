# 老後資金シミュレーター 仕様書

## 1. システム概要

### 1.1 システム名
老後資金シミュレーター（Retirement Simulator）

### 1.2 目的
個人の老後資金計画をシミュレーションし、現役時代から年金受給期間までの資産推移を可視化する。

### 1.3 システム種別
- **アーキテクチャ**: スタンドアロンWebアプリケーション
- **動作環境**: クライアントサイド（ブラウザ）
- **通信**: オフライン動作（ネットワーク通信なし）

### 1.4 仕様確定方針
- テスト期待値は本仕様書を正とする。READMEと実装は本仕様書に一致していることを確認対象とする。
- 税制、年金制度、投資税制は簡易モデルで扱う。実制度との差分は不具合ではなく制約事項として扱う。
- テスト成果物で `要確認` となっていた期待値、許容差、境界条件は、本仕様書の該当節に明記された内容で判定する。

### 2.2 機能詳細仕様

#### F001: 手取り計算機能
**関数名**: `calculateNetMonthly(salaryAnnual)`

**入力**:
- `salaryAnnual` (number): 年収（円）

**処理ロジック**:
1. 社会保険料計算: `年収 × 14%`
2. 課税所得計算: `max(0, 年収 - 社会保険料 - 基礎控除(480,000円))`
3. 所得税計算（簡易累進課税）:
   ```javascript
   const brackets = [
     { up: 1_950_000, rate: 0.05 },
     { up: 3_300_000, rate: 0.10 },
     { up: 6_950_000, rate: 0.20 },
     { up: 9_000_000, rate: 0.23 },
     { up: 18_000_000, rate: 0.33 },
     { up: 40_000_000, rate: 0.40 },
     { up:Infinity, rate:0.45 }
   ];
   ```
4. 住民税計算: `課税所得 × 10%`
5. 手取り年収: `年収 - 社会保険料 - 所得税 - 住民税`
6. 月手取り: `手取り年収 ÷ 12`

**期待値方針**:
- 所得税率ブラケット境界付近の期待値は、上記の簡易計算ロジックのみを正とする。
- 国税庁の実税額表、給与所得控除、復興特別所得税、各種控除、端数処理の実制度はテスト期待値に含めない。
- 境界値テストでは、別途手書きの期待値表ではなく、上記式から算出した期待値を利用する。
- 内部計算値の比較許容差は `±0.01円` とする。画面表示値は `Math.round()` 後の整数円を正とし、桁区切りを含めて比較する。

**出力**:
- `number`: 月手取り額（円、内部計算値）

#### F002: ライフサイクルシミュレーション
**関数名**: `simulateRetirement(opts)`

**入力パラメータ**:
```typescript
interface SimulationOptions {
  startAge: number;           // シミュレーション開始年齢
  retirementAge: number;      // 退職年齢
  pensionStartAge: number;    // 年金開始年齢
  gapIncome: number;          // 退職後収入（月額）
  salary: number;             // 年収
  monthlyPension: number;     // 年金月額
  initialCash: number;        // 開始時現金
  initialInv: number;         // 開始時投資残高
  expenseCurrent: number;     // 現役時生活費（月額）
  expenseGap: number;         // 退職後生活費（月額）
  expenseRetired: number;     // 老後生活費（月額）
  investRate: number;         // 投資率（0-1）
  annualInterest: number;     // 年利回り（0-1）
  eventProb: number;          // イベント発生率（0-1）
  eventTypes: EventType[];    // イベント種別配列
}

interface EventType {
  name: string;    // イベント名
  cost: number;    // 費用
}
```

**処理フロー**:
1. 100歳まで年齢をループ
2. 各年齢で1-12月をループ
3. 年初（1月）に投資残高に利息適用
4. 年齢に応じた収入判定:
   - `age < retirementAge`: 給与収入（年齢に応じた年収で計算、投資積立含む）
   - `retirementAge ≤ age < pensionStartAge`: 退職後収入
   - `age ≥ pensionStartAge`: 年金収入
5. 年齢に応じた生活費差引
6. ランダムイベント処理
7. 現金不足時の投資補填処理
8. 月次結果を配列に追加

**年齢条件の扱い**:
- シミュレーションは `startAge` から100歳12月までを対象とする。
- 収入種別は判定順を仕様とし、給与期間を最優先する。
- `retirementAge <= age < pensionStartAge` の場合のみ退職後収入を使う。
- `pensionStartAge <= retirementAge` のように年金開始年齢が退職年齢以前の場合でも、`age < retirementAge` の間は給与収入を使い、退職後は年金収入を使う。
- 年齢の前後関係が逆転しても入力エラーにはせず、上記の判定順で結果を生成する。

**出力**:
- `string[]`: 月次シミュレーション結果の文字列配列

#### F008: 給与変更機能
**概要**: 転職・昇進による年収変更を複数設定可能

**データ構造**:
```typescript
interface SalaryChange {
  age: number;     // 変更年齢
  salary: number;  // 変更後年収
}
```

**機能**:
- 年齢指定による年収変更
- 複数設定（転職→昇進の組み合わせ可能）
- 動的な項目追加・削除
- トグル表示（設定エリアの表示/非表示）
- 年齢降順ソート（年齢が大きい設定が優先）
- 入力として有効な給与変更は `age >= 1 && age <= 100 && salary > 0` を満たすもののみ
- `age < startAge` の給与変更は、シミュレーション開始時点で適用済みの変更として扱う
- `age === startAge` の給与変更は、開始月から適用する
- `age >= retirementAge` の給与変更は、給与期間外のため結果に影響しない
- 同一年齢の給与変更が複数ある場合は、最後に追加された設定を優先する

**処理ロジック**:
```javascript
function getCurrentSalary(age) {
  let currentSalary = baseSalary;
  const orderedChanges = salaryChanges
    .map((change, index) => ({ ...change, index }))
    .filter(change => change.age >= 1 && change.age <= 100 && change.salary > 0)
    .sort((a, b) => (b.age - a.age) || (b.index - a.index));

  for (const change of orderedChanges) {
    if (age >= change.age) {
      currentSalary = change.salary;
      break;
    }
  }
  return currentSalary;
}
```

## 5. 計算アルゴリズム仕様

### 5.1 投資利回り計算

**適用タイミング**: 毎年1月1日
**計算式**: `新残高 = 前年残高 × (1 + 年利回り)`
**内部計算**: JavaScriptの `number` として保持し、月次処理では丸めない
**表示小数処理**: 画面表示時に `Math.round()` で整数円へ四捨五入
**テスト許容差**: 内部計算値は `±0.01円`、表示値は丸め後の整数円で比較

### 5.2 投資補填アルゴリズム

```javascript
if(cash < 0 && investBal > 0){
  const need = -cash;                         // 必要額
  const maxDraw = investBal / 1.2;            // 税込みで取り崩せる最大補填額
  const draw = Math.min(need, maxDraw);       // 現金へ補填する額
  const tax = draw * 0.2;                     // 20%の税金
  investBal = Math.max(0, investBal - draw - tax);
  cash += draw;                               // 現金増加（補填額のみ）
}
```

**税金考慮の詳細**:
- **税率**: 20%（譲渡所得税等を想定）
- **税金対象**: 現金へ補填した金額
- **投資残高への影響**: 補填額 + 税金を減算
- **現金への影響**: 補填額のみを加算（税金分は現金化されない）
- **残高不足時の扱い**: `補填額 + 税金` が投資残高を超えない範囲で補填し、投資残高は0円未満にしない
- **資産枯渇時の扱い**: 投資残高を使い切っても現金不足が残る場合、現金残高はマイナス表示を許容し、総資産もマイナス表示を許容する
- **例外停止**: 資産枯渇やマイナス総資産は計算停止条件にしない

### 5.3 ランダムイベント発生

**判定**: `Math.random() < eventProb`
**イベント選択**: `eventTypes[Math.floor(Math.random()*eventTypes.length)]`
**実行頻度**: 毎月判定
**入力範囲**: 画面入力の `eventProb` は0%から100%までとし、内部では0から1の確率として扱う
**イベント定義**: `eventProb > 0` の場合、`eventTypes` は1件以上存在すること
**テスト方針**:
- イベント有無の自動テストは、原則として発生率0%または100%で制御する
- イベント種別やイベント列まで固定するテストでは、テスト環境に限り `Math.random()` の差し替え、またはイベント種別配列を1件に限定する
- 本番機能として乱数seed設定は提供しない

## 6. パフォーマンス仕様

### 6.1 計算量
- **時間計算量**: O(年数 × 12) = O(70 × 12) = O(840) ≈ O(1)
- **空間計算量**: O(年数 × 12 × 平均行数) ≈ O(5000行)

### 6.2 応答時間
- **計算処理**: 100ms以下
- **画面描画**: 200ms以下
- **標準測定条件**: デフォルト入力値、イベント発生率0%、デスクトップ相当viewport（1280×720以上）
- **標準測定環境**: PlaywrightのChromiumプロジェクト、または同等の最新安定版Chromium系ブラウザ
- **測定方法**:
  - 計算処理は `simulateRetirement()` 呼び出し前後の `performance.now()` 差分で測定する
  - 画面描画は「開始」操作から `#output` のテキスト更新完了までを測定する
  - ウォームアップ3回後、10回測定し、95パーセンタイルが閾値以下であること
- **連続実行条件**: 入力値を変えながら10回連続実行し、古い結果の混入、JavaScript例外、明確な表示遅延がないこと
- **非対象**: 端末固有の省電力状態、バックグラウンド負荷、ブラウザ拡張による遅延は性能判定の対象外

## 7. エラーハンドリング仕様

### 7.1 入力値検証

**実装方針**: HTML5のバリデーション属性を活用
```html
<input type="number" min="0" step="0.1">
```

**数値入力の許容範囲**:
- `min`、`max`、`step` は画面入力時の制約として扱う。
- ブラウザごとのスピンボタン、貼り付け、空欄、指数表記のUI差異は許容する。
- 合否判定は、最終的にDOM値として取得された値を本仕様のパース規則で処理できること、結果が `NaN` や `Infinity` にならないことを基準とする。
- `salaryChangeAge` は1から100まで、`eventProb` は0から100までを有効入力範囲とする。

### 7.2 例外処理

**不正値の扱い**:
- `parseFloat()` でNaNの場合は0にフォールバック
- 負の値は自然に処理（マイナス資産として表示）
- 有限数ではない値は0にフォールバック
- 給与変更設定では、年齢または年収が未入力、0以下、範囲外、有限数でない場合は無効設定として無視する
- 数値欄へ指数表記が入力できるブラウザでは、ブラウザが有効な数値として保持した場合のみ通常の数値入力として扱う
- 特殊文字列やHTML断片が入力・貼り付け・直接DOM設定された場合でも、HTMLとして実行せず、表示崩れやスクリプト実行につなげない

### 7.3 ブラウザ互換性

**対応ブラウザ**:
- Chrome 最新安定版および1つ前の安定版
- Firefox 最新安定版および1つ前の安定版
- Safari 最新安定版および1つ前の安定版
- Edge 最新安定版および1つ前の安定版

**互換性テストの代表環境**:
- Playwrightの `chromium`、`firefox`、`webkit` プロジェクトを代表環境として扱う
- Safari実機固有の差異は、WebKitで再現できない場合のみ手動確認対象とする
- 旧仕様の `Chrome 60+`、`Firefox 55+`、`Safari 12+`、`Edge 79+` は正式なサポート基準から除外する

**必要JavaScript機能**:

- ただし、本体実装コードのコピーを含むため、仕様式から独立した期待値、E2Eテスト、コードレビューと併用する。
- Playwright E2Eテストは主要ユーザーフロー、ブラウザ互換性、外部通信なし、表示安全性の回帰確認に利用する。

**証跡形式**:
- 自動テスト実行結果は、MarkdownまたはCSVのサマリ、実行ログ、Playwright JSON結果を保存する。
- 失敗時はスクリーンショット、trace、必要に応じてvideoを保存する。
- 手動テストは、確認日時、実行環境、入力条件、期待結果、実結果、判断、スクリーンショット有無を記録する。
- 既存HTMLテストは、ブラウザ上の結果画面スクリーンショットまたはHTML保存、実行ブラウザ、失敗時ログを証跡とする。

**アクセシビリティ確認**:
- キーボードのみで主要操作（入力移動、給与変更表示、給与変更追加・削除、開始）が可能であることを確認する。
- 入力ラベル、ボタン文言、結果表示が支援技術上も意味を推測できることを確認する。
- WCAG 2.2 AAへの正式適合宣言は行わない。基本的なキーボード操作、ラベルの分かりやすさ、画面表示の読み取りやすさを確認対象とする。

**ブラウザ差異の扱い**:
- `number` inputのUI差異はブラウザ仕様差として許容する。
- `min`、`max`、`step` の表示・操作差異そのものではなく、主要入力が可能で結果生成が止まらないことを合否基準とする。

## 11. 制約事項・前提条件

### 11.1 制約事項
- JavaScript無効環境では動作不可
- 計算精度は浮動小数点数の限界内
- 税制・年金制度の将来変更は未考慮
- インフレ・デフレ影響は未考慮
- 投資売却時の税金は一律20%で簡略化（実際の税制は複雑）
- 特定口座（源泉徴収あり）、NISA等の税制優遇制度は未考慮
- シミュレーション結果は目安であり、金融助言、投資助言、税務助言ではない
- 給与と年金の同時受給、退職後の給与所得、繰上げ・繰下げ年金などの複雑な制度は未考慮

### 11.2 前提条件
- モダンブラウザ環境
- JavaScript有効
- 800×600以上の画面解像度
- 800×600未満のスマートフォン幅はベストエフォート表示とし、正式な動作保証対象外
